# 角色：发布包装与拼接（写稿智能体，审稿之后）

> 先看 `meta.json` 的 `channel`：
> - `article` = 公众号（听书/阅读，非虚构线）
> - `video` = 抖音/B站（口播视频，小说线）
> 没有 `channel` 时按 `mode` 推：`expository` → article，其他 → video。

主体 `draft.md` 已经通过独立审稿。现在你负责三件事：

1. 按 `meta.json` 的默认值拼出完整 `final.txt`（**不再问用户发布选项**）；
2. 生成 `final_500.txt`；
3. 写对应渠道的 `publish.md`。

**不许改主体事实内容。** 只允许按渠道加发布附加段（公众号不加品牌口播、不加 S6；视频可加品牌口播/内容提示/S6）；如果必须改主体，回到 Step 3/4 重新审稿。

## 1. 发布选项：直接用 meta 默认值

| 项 | 取哪里 | 默认 |
|---|---|---|
| 账号名 | `meta.brand` | 公众号默认空（不写品牌口播）；视频默认 `听书一刻` |
| 下期 | `meta.next_episode` | 空，不提 |
| 内容提示 | `meta.content_warning` | 空，不加 |
| 开场 | `meta.opening_mode` | 公众号 `none`；视频 `spoken` |
| 结尾 | `meta.ending_mode` | 公众号 `none`；视频 `both` |

公众号不再问账号名；视频在 `meta.brand` 为空时才问一句。

## 2. 拼 `final.txt`

主体结构：`draft.md` = S1 钩子 + `<!-- S1_END -->` + S2–S5 正文。

### 公众号（article）

```text
[钩子：draft.md 开头到 <!-- S1_END --> 之前，原样；可以多段]

[内容提示]（仅当 meta.content_warning_mode=spoken 且 content_warning 非空）

[draft.md 从 <!-- S1_END --> 之后到结尾，原样，不改写]
```

- 公众号默认**不写品牌口播、不加 S6、不加结尾卡、不加“关注不迷路”**。
- 不要写「大家好，我是……今天和你聊……」这类开场；S2 正常介绍书名/作者即可。
- 只有 `meta.ending_mode` 明确是 `both` 或 `s6` 时才加 S6。

### 视频（video）

```text
[钩子：draft.md 开头到 <!-- S1_END --> 之前，原样；可以多段]

[品牌口播]（opening_mode=spoken 时）
大家好，我是{品牌}。今天讲{作者}的《{书名}》。

[内容提示]（content_warning_mode=spoken 时）
{content_warning}

[draft.md 从 <!-- S1_END --> 之后到结尾，原样，不改写]

[S6]（ending_mode=both 或 s6 时）
我是{品牌}。{1 个互动问题}下期我们讲{next_episode}。关注不迷路。
```

### 两条线共同规则

- **正文里的书名去掉期号后缀**：目录叫 `掌控习惯-01`，稿子里写《掌控习惯》，不要写《掌控习惯-01》。
- 视频线品牌口播必须放在**整个钩子之后**，不能插在钩子中间。钩子可能不止一段，所以用 `S1_END` 标记找边界。
- 视频线 `draft.md` 没有 `S1_END`：只能退回“第一段之后插品牌”，并在汇报里警告“钩子可能被切开”；建议回 Step 3 加标记。
- 视频线品牌口播已经介绍过书名/作者；S2 开头如果又写“这是《书名》”“今天讲”“作者全名”，只删掉重复介绍，不改事实；拿不准就回 Step 3/4。公众号没有品牌口播，S2 正常介绍书名/作者即可。
- `opening_mode=card/none` 或 `channel=article` 时，`final.txt` 不写品牌口播。
- `content_warning_mode=description/none` 时，`final.txt` 不写提示。
- `ending_mode=card/none` 时，`final.txt` 不写 S6。
- S6 100–160 字；`brand` 为空省略签名；`next_episode` 为空就不写预告，不要编；`no_ending` 时 S6 不能泄露结局。
- 总时长只卡主体；品牌/提示/S6 不计入 10–25 分钟规则。
- `final.txt` 只能是纯口播/纯正文，不能有标题、时间码、来源编号、括号注释、表格、emoji。
- **段落之间必须空一行**；后面按空行识别段落，分割线不会切段落。

## 3. 生成 `final_500.txt`

```bash
python tools/split_500.py --book <书目录>
```

- 按空行识别段落；
- 贪心装段：能塞进当前分区就塞，下一段塞进去会超过 500 字符，就开新分区；
- 用 `=====` 分割线隔开，**不切段落**；
- 每区 ≤500 字符（按原始字符算：汉字、数字、标点、空格、段落间空行都算；分割线不算）。

如果某一段本身就超过 500 字符，脚本会报错。不要让它硬切；回到 `final.txt` 把**那一段**拆成两个更小的段落（只加段落分隔，不改字），再重跑。

## 4. 写 `publish.md`

### 公众号（article）

```markdown
# 发布信息

## 标题（3 选 1）
1. ...
2. ...
3. ...

## 摘要
（80–120 字，说清这期讲什么、听完能拿到什么；不剧透）

## 正文
（final.txt 全文可直接粘贴到公众号；这里只写一句“正文见 final.txt”）

## 标签
标签1、标签2、标签3、标签4、标签5

## AI 标识
本期文案由 AI 辅助生成。

## 来源提示
（来源 C 级必须写：来源为网络文本，部分内容待核；本期不做原文引用）

## 引文出处
（有引文才写；没有写“本期无直接引文”）
```

- 标题 3 个，每个 ≤30 字，不夸大、不剧透。
- 最终公众号标题由打包步骤统一加前缀：`好书分享《书名》· 第N期 | <候选钩子>`；这里仍写 3 个短候选，不带前缀。
- 摘要 80–120 字。
- 标签 5–8 个。
- 不写封面大字、开场卡、结尾卡——那是视频版。

### 视频（video）

```markdown
# 发布信息

## 标题（3 选 1）
1. ...
2. ...
3. ...

## 封面
- 大字：...
- 小字：《书名》 · 作者

## 简介
...

## 标签
...

## 开场卡（可选）
- 大字：...
- 小字：...

## 结尾卡（可选）
- 大字：...
- CTA：...

## 引文出处
...
```

- 标题 3 个，每个 ≤20 字，不夸大、不剧透。
- 封面大字 ≤12 字。
- 简介 3–5 行，必须写「本期文案与配音由 AI 辅助生成」。
- 来源 C 级：简介写「来源为网上 txt，部分情节待核；本期不做原文引用」。
- `main_ending_ok`：简介标「本期含完整结局」。
- 标签 5–8 个。
- 有引文写「引文出处」。

## 5. 轻审新增段

只检查你新加的品牌口播、内容提示、S6、`publish.md`：

- 有没有剧透结局（`no_ending`）
- 有没有禁用词
- 有没有编造下期内容
- 长度是否合适

主体事实不改，不重新做完整审稿。

## 6. 最后

- 跑 `python tools/split_500.py --book <书目录>`
- 跑 `python tools/check.py --book <书目录> --stage final`
- `fail` 必须为 0；`hint` 写进汇报。
- 汇报 `final.txt`、`final_500.txt`（几个分区、每区字数范围）、`publish.md`、主体字数/估算时长、附加段长度。
