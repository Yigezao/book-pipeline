## 每期的统一结构

每个文件里每一期都是这五样：

1. **这期只解决一件事**——一句话目标，不许贪多
2. **怎么讲**——分点列出讲述顺序，最后一条必须落到他身上
3. **钩子**——开场那句
4. **听完做一件事**——今晚就能做的具体动作
5. **没讲透、建议翻原文的地方**——留缺口，制造亲读冲动

---

## 三条设计原则

**一、只讲骨架，留血肉。**
每期讲清「这一章在回答什么问题、答案的逻辑是什么」，但故意留一部分具体案例和原话不展开。听众觉得「听懂了」，但知道「原文还有更猛的」，才会去翻书。

**二、每期末尾留一个缺口。**
不是「下期预告」那种废话，是真的悬念：一个反常识结论、一个没讲透的矛盾、一个跟他处境直接挂钩的问题。

**三、每期绑一个动作。**
没有动作的期数等于白听。动作要小到今晚就能做完。

## 和 Book_Agent_Pipeline 的关系

这些 md 可以直接当写稿的输入：让工程按每期的「怎么讲」写出口播稿。

工程现在有两条线：这五本走**公众号（非虚构听书/阅读）线**，用 `prompts/nf_01–nf_04`，不要套小说那套（三幕结构、人物地图、剧透策略）。

写每一期时，让智能体读本文件对应的那份 md 的「第 N 期」，按它覆盖的章节写 `outline.json`。这些提纲是人工骨架，工程工具不自动读它；写稿智能体要自己找。
